# ADR 0009：共享 blob 的静态加密格式

- 状态：接受（2026-10-24）
- 关联：`design.md` §2.6、`docs/specs/phase2-sharing.md`

## 背景

私有笔记是端到端加密（服务端只见密文）；共享内容按设计「服务端可读」，但要求**落盘静态加密**，
避免磁盘/备份副本被直接读取明文。共享上传是流式的（`spool_upload`），不能整包进内存再加密。

## 选择

1. **算法**：XChaCha20-Poly1305，**按 1 MiB 分块**独立加密，AAD 绑定块序号。
2. **文件格式（v1）**：
   ```text
   "CB1\0"                          魔数（区分明文/密文）
   重复：nonce(24) ‖ ct_len(u32be) ‖ ciphertext(ct_len)
   ```
   每块明文 ≤ 1 MiB（最后一块可短）；`ct_len ≤ 1 MiB + 16`，解码时据此拒绝异常大块。
3. **AAD**：`"cista.blob.v1" ‖ u32be(块序号)`；块序绑定让重排/拼接可被发现。
4. **密钥**：`CISTA_STATIC_KEY`（32 字节 hex），与 MK、备份仓库密码分开托管；
   非法值拒绝启动，避免静默降级为明文。**生产必须设置**；为空只用于开发/测试（明文落盘）。
5. **写入路径**：`spool_upload` 边收边分块加密；`store_shared_blob`（分享复制路径）整段分块加密。
6. **读取路径**：`serve_blob` 读文件后分块解密再响应（与旧实现一样整文件进内存，上限 100 MiB）。
7. **去重与记账**：内容寻址、`blobs(hash)` 与配额都按**明文**哈希/大小，加密不改变 id 语义。

## 后果

- 好处：磁盘/备份中共享 blob 不含明文；分块使流式写入仍成立；格式自带魔数，配错密钥会显式报错。
- 代价：文件体积增加 `4 + 28 × 块数` 字节；`serve_blob` 整文件读，受单文件 100 MiB 上限约束。
- **兼容性**：启用密钥后，旧的明文 blob 无法读取（会返回 500 并记录 internal error）。
  v1 不内置自动重加密：若已存在明文数据，清空共享目录后重新上传即可。
- 回滚：清空 `CISTA_STATIC_KEY` 会回到明文读写（同样无法读取已有密文），因此回滚需连同数据一起恢复。

## 验证

- `crates/server/src/blob_crypto.rs`：跨块边界往返（1 B / 1 MiB / 1 MiB+1 / 2 MiB+123）、
  流式与整段结果一致、明文输入被拒、篡改与错密钥被拒（3 项单元测试）。
- `crates/server/tests/sharing.rs::shared_blobs_are_encrypted_at_rest_and_decrypt_on_download`：
  上传后磁盘内容不含明文且带魔数，下载解回原文。
