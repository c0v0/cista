# ADR 0002：v1 只实现 B+ 设备签名，不做 bearer 双栈

- 状态：接受（2026-10-24，与 `design.md` §2.2 决策一致）
- 日期：2026-10-24

## 背景

`design.md` §2.2 给出两条认证路线：

- **B+**：每设备一对 Ed25519；服务端只存公钥；请求签名覆盖
  `method‖path‖sha256(body)‖nonce‖ts`；nonce 重放缓存 + ±120s 时钟窗口；吊销 = 删公钥。
- **降级方案**：每设备 256-bit 随机 bearer token，服务端只存 `SHA-256`。

双栈（同时实现两套）会让两条认证路径并存，攻击面并集，且测试必须覆盖 2× 分支。

## 选择

**v1 只实现 B+。** 备选 bearer 方案仅在单独立项时评估，不在同一版本并存。

## 后果

- 好处：服务端没有任何长期共享口令（只有公钥），设备被偷可吊销；日志里没有可重放的凭据。
- 代价：请求签名客户端实现复杂；Web 临时端每次刷新都要重新配对；
  B+ 不防服务端篡改/回滚（见 `design.md` §13 威胁模型）。

## 验证

- `crates/server/tests/authz.rs`：无签名 401；过期时间戳 401；重复 nonce 401；撤销设备后 401。
- 代码里不存在 bearer token 表/字段：`grep -ri "bearer" crates/` 只允许命中注释说明。
